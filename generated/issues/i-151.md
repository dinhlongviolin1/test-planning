# Issue I-151

## Background

This issue tracks an investigation into subsystem-7 and its
interactions with related modules. The goal is to capture the current
behavior, identify gaps, and propose remediation steps for the team.

## Problem

When subsystem-7 receives a request of shape `/api/route-151`,
the response latency exceeds the SLO (p99 ≤ 200ms) under sustained
concurrent load. Profiling traces indicate time is spent in the cache
warming path that runs on every request rather than per-tenant once.

## Expected behavior

- p99 latency ≤ 200ms under 1k rps
- No memory growth in the warming path
- Per-tenant cache rebuilt only on schema change

## Steps to reproduce

1. Start service-7 locally with profile `stress`.
2. Issue 1k concurrent requests to `/api/route-151` for 60 seconds.
3. Capture pprof CPU + heap profile.
4. Observe cache rebuild count > 1k.

## Suggested fix

Move the cache warming into a per-tenant lazy initializer, gated by
schema version. Add a Prometheus counter `cache_rebuild_total` with
tenant label so we can monitor regressions.

## Acceptance criteria

- [ ] p99 ≤ 200ms verified in load test
- [ ] cache_rebuild_total ≤ 1.1× tenant count after warmup
- [ ] no goroutine leak on service-7 shutdown
